## P1（严重）· 出招读条只对自己显示 + 藏拙没实现

### 现状

[ui/table.gd:377] `timer_frac` 只在 `is_me` 时计算，其他玩家恒为 `0.0`。后果：

1. 规则 §8.1「出招用时公开」——标记为**必做、最高优先级**的信息通道——UI 上不存在。
   谁在犹豫、犹豫了多久，全场看不见。
2. 藏拙是纯视图层技能，视图层没做 → **它现在是空技能**。
3. 规格 §15.4 的伪读条完全没写。
   （test_edges 边界 22 里那句 `NOTE: 伪读条在驱动层实现（§15.4），第 4 步验证` 从未兑现。）

### 修法

#### 1a. 真实读条对所有人显示

`table.gd` 已经有 `_turn_time_left`（真人）和 `_bot_think_time / _bot_think_elapsed`（机器人）。
把「当前行动者」的读条算出来发给**每一个** `PlayerPanel`：

```gdscript
# _refresh() 内，替换现有 timer_frac 分支
for i in _player_panels.size():
    var d: Dictionary = v.players[i]
    d["timer_frac"] = 0.0
    d["thinking"] = false
    if gs.phase == Rules.Phase.PLAY and i == int(v.current_player) and d.alive:
        d["thinking"] = true
        if _is_cangzhuo(i, v):                      # 藏拙 → 伪读条，见 1b
            d["timer_frac"] = _fake_timer_frac()
        elif d.is_bot:
            d["timer_frac"] = clampf(_bot_think_elapsed / maxf(_bot_think_time, 0.01), 0.0, 1.0)
        else:
            d["timer_frac"] = clampf(1.0 - _turn_time_left / Rules.PLAY_TIMEOUT_SEC, 0.0, 1.0)
    _player_panels[i].set_data(d, i == HUMAN_ID, i == int(v.current_player))
```

```gdscript
static func _is_cangzhuo(pid: int, v: Dictionary) -> bool:
    return v.skills_enabled and int(v.players[pid].skill) == Rules.Skill.CANGZHUO
```

**方向统一为「从空涨到满」**（0 → 1）。真人自己的读条同样改成涨条，别一个涨一个缩。

`player_panel.gd` 配套：`set_data` 里当 `thinking` 为真时在名字旁显示「…按剑不发」，
读条可见；否则读条隐藏（不是置 0——隐藏，避免一排空条噪声）。

#### 1b. 藏拙伪读条（规格 §15.4，逐条照做）

```gdscript
# table.gd 新增状态
var _fake_T := 0.0          # 本回合伪读条总时长
var _fake_elapsed := 0.0
```

- **进入新的 PLAY 回合时**（`_apply_events` 里已有重置点）：若当前行动者是藏拙持有者，
  `_fake_T = _ui_rng.randf_range(Rules.CANGZHUO_FAKE_MIN, Rules.CANGZHUO_FAKE_MAX)`，`_fake_elapsed = 0.0`。
  ← 注意用 **`_ui_rng`**（P2 新建的表现层 RNG），**不要用 `gs._rng`**。
- `_process` 里 `_fake_elapsed += delta`。
- `_fake_timer_frac()` 返回 `clampf(_fake_elapsed / _fake_T, 0.0, 1.0)`；
  走满后停在 1.0，PlayerPanel 文案改为「仍在沉吟」。
- **真实出招时刻与伪读条无关**；藏拙者真人超时被代出时，外界看到的仍是伪读条（边界 22 的语义）。
- ❌ 不要每帧随机——会抖成噪声，一眼假（规格 §15.4 原话）。

#### 1c. 真人超时的读条与代出

真人（非藏拙）读条走满 = 超时，现有代出逻辑不变。
藏拙真人：**真实倒计时照跑**（自己屏幕上要能看到真实剩余时间——用一个只有 `is_me` 才显示的
小数字标签，别混进公开读条），超时代出照常，公开读条仍是伪值。

## P2（中）· 表现层随机污染内核 RNG 流

### 现状

[ui/table.gd:279] `_bot_think_time` 是纯表现，却从 `gs._rng` 抽。另有 5 处驱动层用 `gs._rng`
（选技能兜底、改弦掷硬币、机器人决策、超时代出挑牌）。

危害：`if _bot_think_elapsed == 0.0` 在任何 `delta == 0` 的帧会多抽一次，内核 RNG 流从此错位；
headless 的可复现测试不走 UI，测不到这个；移植 Durable Object 后，服务端 RNG 流必须只由游戏动作驱动。

### 修法

`table.gd` 建**两个**独立 RNG，`gs._rng` 从驱动层代码里**全部清零**：

```gdscript
var _ui_rng := RandomNumberGenerator.new()       # 纯表现：机器人思考时长、藏拙伪读条
var _driver_rng := RandomNumberGenerator.new()   # 决策代理：Bot.decide、超时代出、机器人技能兜底

func _ready() -> void:
    _ui_rng.randomize()                          # 表现层不需要可复现
    _driver_rng.seed = <本局 seed 派生，如 hash(str(局seed) + "driver")>
```

| 现调用点 | 改用 |
|---|---|
| `_bot_think_time = gs._rng.randf_range(...)` (279) | `_ui_rng` |
| 藏拙伪读条 `_fake_T`（P1 新增） | `_ui_rng` |
| `Bot.decide(view, gs._rng)` (283) | `_driver_rng` |
| 超时代出挑牌 (291) | `_driver_rng` |
| 机器人选技能兜底 (242) | `_driver_rng` |
| 机器人改弦掷硬币 (263-264) | `_driver_rng` |

**验收 grep（必须无输出）**：
```bash
grep -n "gs\._rng" ui/
```

> 注：`Bot.decide` 的签名不变（它本来就接收外部传入的 rng），`bot.gd` 不用动。

## P3（轻）· 驱动层 33 处直读 `gs._players` / 内核私有成员

`ui/table.gd` 有 33 处 `gs._players[...]` / `gs._rng`（P2 修掉 RNG 部分），

### 修法（机械替换，`view_for()` 里字段都已齐全）

| 直读 | 替换 |
|---|---|
| `gs._players[i].name / alive / is_bot / skill / pending_skill_pick 等公开字段` | `view.players[i].*` |
| `gs._players[HUMAN_ID].hand` | `view.you.hand` |
| `gs._players[HUMAN_ID].pending_skill_pick` | `view_for()` **缺此字段** → 在 `you` 里补一个 `pending_skill_pick`（仅本人可见，SKILL_PICK 阶段用）。这是**唯一允许动 `game_state.gd` 的一处**：只加这一个键，加完重跑全部测试 |
| 事件文本渲染里的 `gs._players[e.pid].name` | 开局把 `view.players` 的 `id → name` 缓存成局部字典 `_names`，事件渲染查它 |

或存成成员 `_view` 每次动作后刷新。**目标：`ui/` 下除 `gs.apply(...)`、`gs.view_for(...)`、
`gs.phase`、`gs.current_player`、`gs.winner`、`gs.force_resolve_skill_pick()` 外，不再触碰 `gs` 的任何成员。**

**验收 grep（必须无输出）**：
