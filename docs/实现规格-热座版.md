## 3. 五条铁律（违反则返工）

这一节比后面所有内容加起来都重要。**这套内核将来要翻译成 TypeScript 跑在 Cloudflare Durable Object 里。**

### 铁律 1 · `core/` 必须是纯逻辑
- 一律 `extends RefCounted`，❌ 不得 `extends Node` / `Node2D` / `Control`
- ❌ 不得出现：`get_tree()` `get_node()` `$` `Input` `OS` `Time` `Engine` `await` `signal` 任何 `preload` 场景
- ✅ 只接收数据、返回数据

**自检命令**（必须无输出）：
```bash
grep -rnE "get_tree|get_node|Input\.|OS\.|Time\.|Engine\.|extends Node|\bawait\b|\bsignal\b" core/
```

### 铁律 2 · 所有随机走内核内的带种子 RNG
- `GameState` 持有 `_rng: RandomNumberGenerator`，`new_game` 时 `_rng.seed = seed`
- ❌ 全局 `randi()` `randf()` `randi_range()` `randf_range()` `randomize()` `Array.shuffle()` **一律禁止**
  （`Array.shuffle()` 用的是全局 RNG，必须自己写 Fisher–Yates 走 `_rng`）
- ✅ 同 seed + 同动作串 = **逐事件完全相同的一局**

**自检命令**（必须无输出）：
```bash
grep -rnE "(^|[^_.])(randi|randf|randomize)\(|\.shuffle\(" core/
```

### 铁律 3 · UI 与机器人只能读 `view_for(pid)`
UI 层与 `Bot.decide()` 拿到的必须是**按玩家裁剪过的视图**，不得持有 `GameState` 引用。
这是联机版 `redact()` 的骨架。

**`view_for()` 绝不能包含的五项机密**：
1. 任何人的 `hollow_index`（**包括本人的**，见规则边界 30）
2. 他人的 `hand`
3. `last_played_cards` 的真实牌面（只给 `last_played_count`）
4. 他人的 `probe_result`
5. 他人的 `listen_result`

### 铁律 4 · 状态可序列化
`to_dict()` / `from_dict()` 往返无损，**包括 `_rng.state`**。
只用 `int / float / bool / String / Array / Dictionary`。

### 铁律 5 · 内核不推进时间
内核**没有计时器**。倒计时与超时判定全在驱动层；超时后由驱动层送一个普通 `PLAY` 动作进来。
`Rules` 里的时间常量只是给 UI 读的，内核不许引用。

const PLAY_TIMEOUT_SEC   := 20.0
const SKILL_PICK_SEC     := 15.0
const SWAP_WINDOW_SEC    := 5.0

const CANGZHUO_FAKE_MAX  := 18.0
const BOT_THINK_MIN_SEC  := 1.5
const BOT_THINK_MAX_SEC  := 8.0

# ---------- 表情 ----------
const EMOTES := ["冷笑", "抱拳", "拂袖", "摇头", "抚须", "请"]

static func build_deck() -> Array:
    var d := []
    # 必须按枚举固定顺序遍历，不能 for suit in DECK_COUNTS —— 字典键序不保证稳定，
    # 而这个数组紧接着要被洗牌，键序漂移会直接破坏可复现性（§19 坑 4）。
    for suit in [Suit.DAO, Suit.JIAN, Suit.ZHANG, Suit.HUAJIN]:
        for i in DECK_COUNTS[suit]:

    return card == declared_suit or card == Suit.HUAJIN

## 7. Action

### 7.1 Schema

```gdscript
{"type": "PICK_SKILL",    "pid": int, "skill": int}
{"type": "USE_GAIXIAN",   "pid": int, "suit": int}          # suit ∈ PLAYABLE_SUITS
{"type": "USE_TINGJIN",   "pid": int, "card_pos": int}      # 0..last_played_count-1
{"type": "USE_BIANXUSHI", "pid": int, "stone": int}         # 1..6
{"type": "PLAY",          "pid": int, "indices": Array[int]}# 手牌下标，1..3 个，互不重复
{"type": "CHALLENGE",     "pid": int}
{"type": "EMOTE",         "pid": int, "emote": int}
```

### 7.2 合法性条件（`legal_actions()` 与 `apply()` 必须用**同一份**判定，抽成 `_is_legal(a)`）

| 动作 | 全部条件 |
|---|---|
| `PICK_SKILL` | `skills_enabled` ∧ `phase == SKILL_PICK` ∧ 本人 `pending_skill_pick == NONE` ∧ `skill ∈ ALL_SKILLS` |

> **§7.2 勘误（v2）**：早先版本让驱动层在超时时送 `PICK_SKILL{skill: NONE}`，但 `NONE = -1` 不在 `ALL_SKILLS` 里，
> 会被合法性校验拒绝，导致 SKILL_PICK 阶段永远收不了尾。
> 正确做法：内核提供 `force_resolve_skill_pick()`，驱动层超时后调用它收尾，未提交者按规则 §3.5 进落选池随机分配。
> §14 的对应描述同步更正。
| `USE_GAIXIAN` | `skills_enabled` ∧ `phase == SWAP_WINDOW` ∧ `skill == GAIXIAN` ∧ `skill_uses_left > 0` ∧ `suit ∈ PLAYABLE_SUITS` ∧ `alive` |
| `USE_TINGJIN` | `skills_enabled` ∧ `phase == PLAY` ∧ `pid == current_player` ∧ `skill == TINGJIN` ∧ `skill_uses_left > 0` ∧ `last_player_who_played != -1` ∧ **`last_player_who_played != pid`**（边界 31）∧ `0 <= card_pos < last_played_cards.size()` ∧ 本轮尚未用过 |
| `USE_BIANXUSHI` | `skills_enabled` ∧ `phase == PLAY` ∧ `pid == current_player` ∧ `skill == BIANXUSHI` ∧ `skill_uses_left > 0` ∧ `1 <= stone <= 6` ∧ **`stone > steps_taken`**（未踏过，边界 15） |
| `PLAY` | `phase == PLAY` ∧ `pid == current_player` ∧ `1 <= indices.size() <= 3` ∧ 下标合法且互不重复 |
| `CHALLENGE` | `phase == PLAY` ∧ `pid == current_player` ∧ `last_player_who_played != -1`（边界 1）∧ **`last_player_who_played != pid`**（边界 31） |
| `EMOTE` | 任何阶段、任何存活玩家 |

> `USE_TINGJIN` / `USE_BIANXUSHI` **不消耗行动权**：发动后 `current_player` 不变，
> 该玩家仍必须再送一个 `PLAY` 或 `CHALLENGE`（规则 §4.4）。

### 7.3 非法动作的处理契约

`apply()` 遇到非法动作：**不修改任何状态**，返回
```gdscript
[{"type": "REJECTED", "reason": "<机器可读的短标识>", "action": <原动作>}]
```
❌ 不要 `assert` 崩掉，❌ 不要静默忽略。测试要能对 `REJECTED.reason` 断言。

## 10. 状态机

```
new_game()
   给每人 hollow_index = _rng.randi_range(1, 6)
   round_starter = _rng.randi_range(0, N-1)
   round_number = 0
   skills_enabled ? phase = SKILL_PICK : _start_round()
        │
        └─ SKILL_PICK：收齐全部 PICK_SKILL（或驱动层超时代填 NONE）
                       → _resolve_skill_pick() → _start_round()
_start_round():
   round_number += 1
   suit_changed_by = -1
   current_suit = PLAYABLE_SUITS[_rng.randi_range(0, 2)]
   洗全部 30 张（Fisher–Yates 走 _rng），给每个存活玩家发 5 张   ← 边界 32
   deck_remaining = 30 - alive_count * 5
   last_player_who_played = -1;  last_played_cards = [];  discard_count = 0
   current_player = round_starter
   若有存活玩家持未用的改弦 → phase = SWAP_WINDOW
   否则                      → phase = PLAY
        │
        └─ SWAP_WINDOW：收到 USE_GAIXIAN 或驱动层送 PASS_WINDOW → phase = PLAY

PLAY 循环：
   PLAY(indices)  → 旧的 last_played_cards 进弃牌堆(discard_count += 它的张数)
                    last_played_cards = 打出的牌;  last_player_who_played = pid
                    _advance_turn() 失败 → _end_round(-1)
   CHALLENGE()    → phase = REVEAL → 立即 _resolve_reveal()

_resolve_reveal():
   honest = last_played_cards 全部满足 is_truthful(c, current_suit)
   若 honest:
        victim = 拆招者
        若 skills_enabled ∧ 上家.skill == HOUFA ∧ round_number >= 上家.houfa_ready_round:
             上家.houfa_ready_round = round_number + HOUFA_COOLDOWN_ROUNDS
             _retreat(victim, HOUFA_TOTAL_STEPS)   # 2 步
        否则 _retreat(victim, 1)
   否则:
        victim = 上家;  _retreat(victim, 1)
   _end_round(victim.id)

_end_round(retreater_id):
   若 retreater_id == -1:  round_starter = 本轮 round_starter 的下家（跳过出局者）
   否则若 该玩家 alive:     round_starter = retreater_id
   否则:                    round_starter = 他的下家（跳过出局者）
   存活数 == 1 → winner = 那个人; phase = GAME_OVER
   否则 → _start_round()
```

## 11. 关键子过程（完整代码，别处不得复制粘贴第二份）

### 11.1 `_retreat` —— 唯一的退步实现

```gdscript
func _retreat(p: Dictionary, steps: int) -> void:
    for i in steps:
        if not p.alive:
            return
        # 豁口判定必须在 steps_taken += 1 之前！
        if p.has_gap:                                   # 规则 §3.3① 豁口模型
            p.alive = false
            _emit_fall(p)
            return
        var from_step: int = p.steps_taken
        p.steps_taken += 1
        _emit({"type": "RETREAT", "pid": p.id,
               "from_step": from_step, "to_step": p.steps_taken})
        if p.steps_taken == p.hollow_index:
            if skills_enabled and p.skill == Rules.Skill.JINZHONGZHAO \
               and not p.golden_bell_used:
                p.golden_bell_used = true
                p.skill_uses_left = 0
                p.has_gap = true                        # 石板碎裂，留下豁口
                _emit({"type": "GOLDEN_BELL", "pid": p.id})
            else:
                p.alive = false
                _emit_fall(p)
                return
```

> **最容易写错的地方**：`has_gap` 的检查顺序。放到 `steps_taken += 1` 之后，
> 金钟罩救过的人会多活一步，直接违反规则边界 8 / 10。
>
> **注意**：`steps_taken` 永远不会超过 `hollow_index`（到了就出局或留豁口），
> 所以规则 §5 那张 1/6 → 1/1 的概率表自动成立，不需要额外代码保证。

### 11.2 `_advance_turn` —— 找下一个能行动的人

```gdscript
func _advance_turn() -> bool:
    var n := _players.size()
    for i in range(1, n + 1):
        var cand := (current_player + i) % n
        var p: Dictionary = _players[cand]
        if p.alive and p.hand.size() > 0:
            if cand != current_player:
                current_player = cand
            else:
                current_player = cand          # 只剩自己有牌，回到自己（边界 31）
            return true
        if p.alive and p.hand.is_empty() and cand != current_player:
            _emit({"type": "SKIPPED", "pid": cand, "reason": "empty_hand"})
    return false        # 无人可行动 → 本轮全员出尽（边界 4）
```

> **「上家」不由座位决定**：`last_player_who_played` 是**最近一个真正出过牌的人**，
> 被跳过的空手玩家不会更新它（规则 §9.1、边界 21）。

### 11.3 `_resolve_skill_pick` —— 同时选 + 冲突随机裁决

```gdscript
func _resolve_skill_pick() -> void:
    var by_skill := {}                     # skill -> [pid...]
    var losers := []
    for p in _players:
        var s: int = p.pending_skill_pick
        if s == Rules.Skill.NONE:
            losers.append(p.id)            # 超时未选，直接进落选池
        else:
            if not by_skill.has(s): by_skill[s] = []
            by_skill[s].append(p.id)

    var taken := {}
    # 键必须排序后遍历，否则字典序不确定 → 违反铁律 2 的可复现性
    var skills_sorted := by_skill.keys()
    skills_sorted.sort()
    for s in skills_sorted:
        var claimants: Array = by_skill[s]
        claimants.sort()                   # 同上，先定序再随机
        var winner_idx := _rng.randi_range(0, claimants.size() - 1)
        var w: int = claimants[winner_idx]
        taken[s] = w
        for c in claimants:
            if c != w: losers.append(c)

    var remaining := []
    for s in Rules.ALL_SKILLS:
        if not taken.has(s): remaining.append(s)

    losers.sort()
    _shuffle(losers)                       # 走 _rng 的 Fisher–Yates
    var randomized := []
    for pid in losers:
        var idx := _rng.randi_range(0, remaining.size() - 1)
        var s: int = remaining[idx]
        remaining.remove_at(idx)
        taken[s] = pid
        randomized.append(pid)

    for s in taken:
        var p: Dictionary = _players[taken[s]]
        p.skill = s
        p.skill_uses_left = Rules.SKILL_USES[s]
        p.houfa_ready_round = 0
    _emit({"type": "SKILLS_ASSIGNED", "assignments": ..., "randomized": randomized})
```

> **可复现性的陷阱**：GDScript 的 `Dictionary.keys()` 顺序**不保证跨版本稳定**。
> 任何对字典的遍历，只要后面跟着 `_rng` 调用，都必须**先把键排序**。
> 这是铁律 2 最容易漏掉的一个口子。

### 11.4 `_shuffle` —— 唯一允许的洗牌

```gdscript
func _shuffle(arr: Array) -> void:
    for i in range(arr.size() - 1, 0, -1):
        var j := _rng.randi_range(0, i)
        var t = arr[i]; arr[i] = arr[j]; arr[j] = t
```
❌ **禁止 `Array.shuffle()`** —— 它走的是全局 RNG，直接破坏可复现性。

### 11.5 `to_dict` / `from_dict` 的 RNG

```gdscript
# to_dict
d["_rng_state"] = _rng.state
d["_seed"] = _seed
# from_dict
gs._rng = RandomNumberGenerator.new()
gs._rng.seed = d["_seed"]
gs._rng.state = d["_rng_state"]     # 必须恢复 state，只恢复 seed 会回到开局
```

|---|---|---|
| 6' | `honest = true` → 拆招者 P4 冤枉了人 | `REVEALED{P2,[刀,化劲],刀,honest:true}` |

## 13. `core/bot.gd`

```gdscript
class_name Bot
extends RefCounted

# 只接收 view，绝不接触 GameState —— 这同时也是铁律 3 的活体测试
static func decide(view: Dictionary, rng: RandomNumberGenerator) -> Dictionary:
    var me: Dictionary = view.you
    var legal: Array = view.legal_actions
    var can_challenge := _has_type(legal, "CHALLENGE")

    if can_challenge:
        var p := 0.15
        var cnt: int = view.last_played_count
        if cnt == 3: p += 0.25
        elif cnt == 2: p += 0.10
        # 我手里真牌很多 → 别人手里应该没多少
        var mine := 0
        for c in me.hand:
            if c == view.current_suit or c == Rules.Suit.HUAJIN: mine += 1
        if mine >= 5: p += 0.30
        if me.steps_taken >= 3: p *= 0.40            # 怕死
        var up: Dictionary = view.players[view.last_player_who_played]
        if view.skills_enabled and up.skill == Rules.Skill.HOUFA \
           and view.round_number >= up.houfa_ready_round:
            p *= 0.30                                 # 更怕
        if up.steps_taken >= 4: p += 0.15             # 赌他死
        if rng.randf() < clampf(p, 0.0, 0.95):
            return {"type": "CHALLENGE", "pid": me.id}

    # 出牌
    var truths := []
    for i in me.hand.size():
        if me.hand[i] == view.current_suit or me.hand[i] == Rules.Suit.HUAJIN:
            truths.append(i)
    if truths.size() >= 1:
        var r := rng.randf()
        var n := 1 if r < 0.60 else (2 if r < 0.90 else 3)
        n = mini(n, truths.size())
        return {"type": "PLAY", "pid": me.id, "indices": truths.slice(0, n)}
    return {"type": "PLAY", "pid": me.id,
            "indices": [rng.randi_range(0, me.hand.size() - 1)]}
```

**技能**：首版**随机时机、随机合法目标**发动即可。不做技能 AI，浪费时间。
机器人是测试脚手架，不是卖点（规则 §10）。

## 14. 驱动层（`ui/table.gd`）

内核不管时间（铁律 5），驱动层负责：

```
_process(delta):
  if gs.phase == GAME_OVER: return
  if 当前该动的是真人:
      推进倒计时（Rules.PLAY_TIMEOUT_SEC）
      超时 → 从 legal_actions 里挑一个 PLAY（随机 1 张）送进内核
  else 当前该动的是机器人:
      首次进入该回合时抽一个 think_time ∈ [BOT_THINK_MIN_SEC, BOT_THINK_MAX_SEC]（走 gs 的 rng）
      到点 → Bot.decide(gs.view_for(bot_id), rng) → gs.apply()
  把 apply() 返回的事件推进动画队列，**逐个播放**，播完再处理下一个动作
```

> **机器人必须有可见的思考时间**，否则它们瞬间出完，真人根本看不清发生了什么。

## 19. 十个最容易踩的坑

1. **`has_gap` 判定写在 `steps_taken += 1` 之后** → 金钟罩救过的人多活一步（边界 8/10）
2. **用座位号当「上家」** → 空手玩家被跳过后拆错人（边界 21）
3. **`Array.shuffle()`** → 走全局 RNG，可复现性当场作废（铁律 2）
4. **遍历 `Dictionary.keys()` 后紧跟 `_rng` 调用** → 键序不保证稳定，同 seed 跑出不同结果（§11.3）
5. **`from_dict` 只恢复 `seed` 不恢复 `state`** → 反序列化后回到开局的随机序列（§11.5）
6. **`legal_actions()` 和 `apply()` 各写一份合法性判定** → 两边必然漂移，抽成 `_is_legal()`
7. **听劲/辨虚实消耗了行动权** → 规则 §4.4 明确说不消耗
8. **`REVEALED` 事件之外的事件里带了牌面** → 泄密（§8）
9. **`view_for()` 里塞了本人的 `hollow_index`** → 规则边界 30，本人也不能看
10. **机器人直接读 `GameState`** → 铁律 3 失去活体测试，联机时才发现 view 信息不够

## 20. 给执行者的三条

1. **不要自己发明规则。** 有歧义 → 停下来报告，不要猜。上一个项目就是猜出来的规则堆到最后没人敢改。
2. **不要提前优化，不要提前做美术。** 本步产出是一份能跑对的规则内核。
3. **`core/` 的纯净度是本步最重要的交付物**，比 UI 好不好看重要一百倍。
   它下一步要被翻译成 TypeScript 塞进 Cloudflare Durable Object。
   任何一处 `get_tree()` 或全局 `randi()`，到那时都是要重写的债。
